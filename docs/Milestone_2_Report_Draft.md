# Section 2: Prompt and Solution Design

## 2.1 Solution Narrative & Design Rationale

### The Problem Statement
Higher education students, researchers, and self-learners routinely interact with vast quantities of unstructured academic materials, including lecture slide transcripts, unformatted class notes, and dense textbook PDF chapters. When learners attempt to synthesize these materials using conventional zero-shot Large Language Model (LLM) prompts, three critical failure modes emerge:
1. **Hallucination of External Knowledge:** Standard LLM prompts draw upon pre-training memory to invent unmentioned examples, external theorems, and extraneous historical context, confusing students preparing for strict curricular examinations.
2. **Output Collapse & Dilution:** When a single prompt requests an executive summary, terminology glossary, and examination questions simultaneously, the model experiences cognitive overload, leading to truncated summaries, shallow 2-word definitions, and simplistic recall questions.
3. **Format Volatility:** Unconstrained single prompts generate inconsistent markdown formats, preventing programmatic compilation or clean tabbed presentation.

### Target Users & Use Cases
- **University Undergraduate & Graduate Students:** Rapidly converting 20-page lecture slide decks into structured revision packs before midterms and finals.
- **Course Instructors & Teaching Assistants:** Rapidly generating grounded 5-question pop quizzes and key-concept study guides directly from weekly lecture notes.
- **Independent Researchers:** Synthesizing domain literature into concise glossaries and analytical self-assessment questions.

### System Inputs & Outputs
- **Input:** Multi-page academic PDF documents (processed via `pypdf`) or raw lecture notes pasted into a multi-line text editor.
- **Output:** A three-part grounded study pack formatted in structured Markdown:
  1. *Executive Summary:* Thematic headers with bulleted key findings.
  2. *Key Terms & Definitions:* High-yield glossary formatted as `- **[Term]**: [Definition]`.
  3. *Exam-Style Practice Q&A:* Exactly 5 rigorous questions (Conceptual, Applied, Analytical) with model answers and grounding citations. If information is absent, the model explicitly outputs: *"Not provided in notes."*

### Why 3 Chained Prompts Were Chosen Over Milestone 1's Single Monolithic Prompt
In Milestone 1, we utilized a single monolithic prompt (`prompts/v1/baseline_prompt.txt`). While functional for trivial paragraphs, it broke down on dense academic notes. In Milestone 2, we transitioned to a **3-step sequential prompt chain (`P1` → `P2` → `P3`)** for several key reasons:
1. **Context & Attention Specialization:** Decomposing the generation into three dedicated tasks (`P1_summary`, `P2_key_terms`, `P3_practice_qa`) ensures that 100% of the model's attention and output token budget in each step is focused on a single pedagogical goal.
2. **Conditioned Inter-Step Dependencies:** 
   - Step 2 (`P2`) receives both the original notes AND the concise summary generated by `P1`, allowing it to identify terminology that directly reinforces core themes.
   - Step 3 (`P3`) receives both the original notes AND the extracted glossary from `P2`, ensuring practice questions directly evaluate student mastery of the verified key terms.
3. **Error Isolation & Observability:** If a failure occurs, the user and developer can identify whether the failure originated in the summarization, terminology extraction, or question generation stage.

### Why Gemini 2.5 Flash + Streamlit Was Selected
- **Google Gemini 2.5 Flash (`gemini-2.5-flash`)**:
  - Chosen for its sub-3-second inference speed, strong reasoning capabilities, cost efficiency, and high fidelity to negative constraints and system instructions.
  - Configured at a deterministic temperature of `0.2` to prioritize factual reproduction over creative generation.
- **Streamlit (`streamlit` v1.67)**:
  - Enables rapid development of a modern, reactive single-page interface with native password-masked text inputs, dynamic model selectors, tabbed displays, and client-side markdown export (`st.download_button`).

### Key Enhancements Since Milestone 1
- **Architectural Shift:** From a single zero-shot prompt (`v1`) to an intermediate grounded prompt (`v2`), and finally to a 3-step sequential prompt chain (`v3`).
- **Temperature Optimization:** Reduced from an uncontrolled default of `0.7` down to `0.2`.
- **Pre-LLM Guardrail Filtering:** Implemented heuristic checks in `code/app.py` catching empty strings, inputs under 30 characters, keyboard mash, and non-academic noise before calling the API.
- **PDF Extraction Integration:** Replaced manual plain-text copying with automated multi-page extraction via `pypdf`.

### Prompt Sheet 1: Executive Summary Generator (`P1_summary`)

- **Prompt ID & Name:** `P1_summary` | Executive Summary Generator
- **Workflow Step:** Step 1 of 3 (Initial Ingestion & Thematic Synthesis)
- **1-Line Purpose:** Ingests raw lecture notes and synthesizes a structured, bulleted executive summary grounded strictly in the text.
- **Tool & Model:** Google GenAI SDK (`google-genai`), Model: `gemini-2.5-flash`
- **Settings:** Temperature: `0.2`, Top-P: `0.95`, Max Output Tokens: `2048`
- **Count of Examples:** `0` (Zero-shot instructed with strict negative rules)
- **Variable Definitions:**
  - `{lecture_notes}`: Raw text extracted from uploaded PDF or pasted by user.
- **Output Format:** Markdown with Level-2/3 thematic headers and bullet points.

#### Full Prompt Template
```text
You are an expert academic tutor and concise summarizer specializing in higher education materials.

INPUT LECTURE NOTES:
"""
{lecture_notes}
"""

TASK:
Generate a comprehensive, clear, and bulleted executive summary of these lecture notes.

STRICT GROUNDING RULES:
1. Base your summary STRICTLY and EXCLUSIVELY on the provided lecture notes.
2. Do NOT extrapolate, hallucinate, or incorporate outside knowledge not present in the text.
3. Organize the summary logically with thematic section headings (using Markdown ## and ###) followed by concise, impactful bullet points.
4. Highlight central concepts, methodologies, core arguments, and experimental or theoretical conclusions explicitly described.
```

#### Real Sample Run (Input & Output)
- **Sample Input (`{lecture_notes}`):**
  > *"Relational database normalization organizes tables to minimize redundancy. 1NF enforces atomic attribute values and primary keys. 2NF removes partial functional dependencies on composite keys. 3NF removes transitive dependencies where non-key attributes depend on other non-key attributes. Boyce-Codd Normal Form (BCNF) requires that for every functional dependency X -> Y, X must be a superkey."*
- **Real Model Output (`{summary}`):**
  > `## Relational Database Normalization`  
  > `- Core Goal: Systematic organization of relational tables to eliminate data redundancy and preserve logical dependencies.`  
  > `### Normal Form Hierarchy`  
  > `- 1NF: Mandates that all attribute values are atomic and every tuple is uniquely identifiable via a primary key.`  
  > `- 2NF: Eliminates partial functional dependencies; all non-prime attributes must depend on the whole candidate key.`  
  > `- 3NF: Eliminates transitive dependencies (non-key attribute depending on another non-key attribute).`  
  > `- BCNF: Enforces a stricter condition where for every functional dependency X -> Y, the determinant X must strictly be a superkey.`

## 4.3 Known Limitations & Milestone 3 Roadmap

1. **Lack of OCR for Scanned Image-Only PDFs:**
   - *Limitation:* The current `pypdf` parser extracts text from digital PDF streams. Image-only scans return empty text buffers, triggering the heuristic rejection gate.
   - *Milestone 3 Roadmap:* Integrate Tesseract OCR or Gemini 2.5 Flash native multimodal PDF ingestion.
2. **Context Compression on Long Multi-Chapter Texts:**
   - *Limitation:* Ingesting an entire 60-page textbook chapter in a single pass can dilute the prompt chain's attention on middle sections.
   - *Milestone 3 Roadmap:* Implement a chunked Retrieval-Augmented Generation (RAG) pipeline with recursive text splitting and local vector indexing (e.g., ChromaDB).
3. **Static Practice Q&A vs. Interactive Assessment:**
   - *Limitation:* Practice questions are presented as static markdown text with answer keys visible immediately below each question.
   - *Milestone 3 Roadmap:* Build an interactive quiz mode with hidden answer toggles, student input fields, and LLM-driven personalized grading feedback.

### 1. Executive Summary & Architectural Overview
The **AI-Powered Study Pack Generator** is an automated educational pipeline designed to transform unstructured lecture materials (textbook excerpts, lecture notes, or syllabus PDFs) into strictly-grounded, multi-part study packs comprising an executive summary, domain terminology definitions, and exam practice questions with answer keys. 

In Milestone 1, a single monolithic prompt was employed, resulting in severe output dilution, frequent hallucinations of unmentioned textbook facts, and brittle formatting. In Milestone 2, we refactored the system into a **3-stage sequential Prompt Engineering Chain (`P1` → `P2` → `P3`)** hosted within a lightweight, responsive **Streamlit** web application and backed by **Google Gemini 2.5 Flash** via the `google-genai` SDK. By decomposing the cognitive load across dedicated prompt stages and enforcing strict negative grounding constraints at temperature `0.2`, the system achieves zero ungrounded extrapolations on standard academic benchmark texts.

### 2. Tools, Frameworks & Foundation Model Selection
- **Foundation Model (`gemini-2.5-flash`)**: Selected for its exceptional reasoning-to-latency ratio, high instruction-following adherence, and native support for structured markdown. Operating at a deterministic temperature of `0.2`, it prioritizes factual fidelity and eliminates creative hallucination.
- **Client SDK (`google-genai` v3.6.1)**: Utilizes Google's modern GenAI Python SDK (`genai.Client`) with explicit `GenerateContentConfig(temperature=0.2)`.
- **Application Framework (`Streamlit` v1.67)**: Provides a clean, modern single-page application (SPA) featuring password-masked API key handling, dynamic model switching, real-time step execution status (`st.status`), tabbed outputs, and client-side markdown export (`st.download_button`).
- **Document Processing (`pypdf` v7.1.1)**: Performs client-side PDF parsing across all document pages, extracting pure text buffers prior to validation and inference.
- **Environment Management (`python-dotenv`)**: Securely loads local credentials from `.env` without exposing keys to version control.

### 3. Prompt Chaining Design (`P1` → `P2` → `P3`)
Rather than forcing the LLM to simultaneously summarize, extract terms, and author exam questions in a single context window, our design partitions the task into three interdependent stages:
1. **`P1_summary` (Executive Summary Generator)**:
   - *Input:* `{lecture_notes}`
   - *Objective:* Ingests raw text, identifies thematic core topics, and constructs a structured executive summary using Markdown headers (`##`, `###`) and concise bullet points.
   - *Constraint:* Strict textual grounding; zero external extrapolation.
2. **`P2_key_terms` (Key Terms & Definitions Extractor)**:
   - *Input:* `{lecture_notes}`, `{summary}`
   - *Objective:* Scans the notes guided by the P1 summary to identify technical keywords, acronyms, and formulas, generating a bolded markdown glossary (`- **[Term]**: [Definition]`).
   - *Constraint:* Terms not explicitly defined in the text are defined strictly within their recorded context rather than from external training memory.
3. **`P3_practice_qa` (Exam Practice Q&A Generator)**:
   - *Input:* `{lecture_notes}`, `{key_terms}`
   - *Objective:* Generates exactly 5 exam-style questions (2 Conceptual, 2 Applied/Analytical, 1 Synthesis) with model answers and grounding citations.
   - *Constraint:* If an exam question asks about a topic missing from the notes, the model is strictly mandated to answer: *"Not provided in notes."*

### 4. Quantitative Evaluation & Prompt Evolution Summary
We evaluated 10 standard university lecture excerpts across the 3 prompt iterations (`v1` Milestone 1 Baseline, `v2` Grounded Monolith, and `v3` Final Sequential Chain):
- **Hallucination Rate:** Dropped from 60% in v1 to 20% in v2, and to **0% in v3**.
- **Schema & Markdown Compliance:** Improved from 40% in v1 to 80% in v2, and reached **100% in v3**.
- **Assessment Quality:** Shifted from erratic question counts (2-4 simple questions) in v1 to **exactly 5 multi-tier questions with answer keys and grounding citations** in v3.
- **Pre-LLM Guardrail Gate:** Completely absent in v1/v2; successfully blocks invalid inputs and noise in v3 before calling APIs.

### 5. Current Limitations & Failure Modes
1. **Scanned Image-Only PDFs:** Pure bitmap scans lacking text layers return empty strings and trigger validation rejections.
2. **Heavy Colloquial/Bilingual Notes:** Hinglish phrasing occasionally creates inconsistent mixing of Romanized Hindi and English grammar in definitions.
3. **Multi-line Math Equations:** Raw non-LaTeX ASCII equations in notes occasionally encounter character shifts during PDF text extraction.
4. **Context Dilution on Large Textbooks:** Single-pass processing of 50+ page documents causes attention compression in middle sections.
